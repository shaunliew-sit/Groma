## Region Duplicate Issue - Root Cause & Solutions

Based on your debug output, the issue is now **crystal clear**:

## Root Cause

**The model generates duplicate box tokens in its text output**, not because the IoU selection is broken, but because **the model is trained for HOI description rather than pure grounding**.

### Evidence from Debug Output

```
[person]
  Generated text: The <p> person </p> <roi> <r8> </roi> is <p> riding </p> the <p> boat </p> <roi> <r8> </roi>
  Box tokens found: [32022, 32022]
  Mapped to region indices: [8, 8]
  ⚠️  DUPLICATE REGIONS DETECTED: [8]
     Region R8 selected 2 times
```

**What's happening**:
- The model generates: `"The person <r8> is riding the boat <r8>"`
- It mentions R8 twice (once for person, once for boat) because it's describing a HOI relationship
- Both tokens map to index 8 → same box selected twice

**This is NOT a bug** - it's the expected behavior for a model trained on HOI **interaction description**!

## Solutions

### Solution 1: Post-Processing Deduplication (Quick Fix)

**Best for**: Immediate evaluation without retraining

Add duplicate removal based on IoU threshold:

```python
def deduplicate_boxes(boxes, iou_threshold=0.7):
    """Remove duplicate boxes using NMS-style approach"""
    if len(boxes) == 0:
        return boxes, []

    from torchvision.ops import box_iou
    import torch

    # Convert to tensor
    boxes_tensor = torch.tensor(boxes)

    # Calculate IoU matrix
    ious = box_iou(boxes_tensor, boxes_tensor)

    # Find unique boxes
    keep = []
    skip = set()

    for i in range(len(boxes)):
        if i in skip:
            continue
        keep.append(i)

        # Mark similar boxes as duplicates
        for j in range(i + 1, len(boxes)):
            if ious[i, j] > iou_threshold:
                skip.add(j)

    return [boxes[i] for i in keep], keep
```

Add this to the evaluation script after box selection:

```python
# After line 729 in eval_hico_ground.py
selected_boxes = rescale_box(selected_boxes, img_shape).tolist()

# Add deduplication
selected_boxes, keep_indices = deduplicate_boxes(selected_boxes, iou_threshold=0.7)
selected_box_inds = [selected_box_inds[i] for i in keep_indices]
```

### Solution 2: Token-Level Deduplication (Better Fix)

**Best for**: Cleaner solution without changing model behavior

Deduplicate at the token level before box selection:

```python
# After line 688 in eval_hico_ground.py
selected_box_inds = [
    idx for idx in selected_box_inds
    if idx < len(pred_boxes)
]

# Add: Remove duplicate indices while preserving order
seen = set()
unique_box_inds = []
for idx in selected_box_inds:
    if idx not in seen:
        seen.add(idx)
        unique_box_inds.append(idx)

selected_box_inds = unique_box_inds
```

This is simpler and faster than box-level deduplication.

### Solution 3: Prompt Engineering (Medium-term Fix)

**Best for**: Improving without retraining

Change the query prompt to encourage unique boxes:

Current prompt:
```python
"Locate all <person> in this image"
```

Try:
```python
"List each <person> in this image separately"
# or
"Find all distinct <person> instances"
# or
"Give me the bounding box for each individual <person>"
```

### Solution 4: Retrain with Grounding-Specific Data (Long-term Fix)

**Best for**: Permanent solution

The model was trained on HOI interaction data where mentioning the same region twice makes sense:
- "The person is riding the boat" → person R8, boat R8 (same interaction)

For pure grounding, you need data like:
- "person: R8, R10, R15" → separate instances
- "boat: R4, R7" → separate instances

**Training data format needed**:
```json
{
  "image": "img.jpg",
  "conversations": [
    {
      "from": "human",
      "value": "Locate all person in this image"
    },
    {
      "from": "gpt",
      "value": "<roi><r8></roi>, <roi><r10></roi>, <roi><r15></roi>"
    }
  ]
}
```

Instead of:
```json
{
  "from": "gpt",
  "value": "The <p>person</p><roi><r8></roi> is riding the <p>boat</p><roi><r8></roi>"
}
```

## Recommended Approach

For **immediate evaluation**, use **Solution 2** (token-level deduplication):

1. It's a 3-line code change
2. Preserves the first occurrence of each region
3. No performance impact
4. Doesn't change box coordinates

For **better long-term results**, combine:
- **Solution 2** for current evaluation
- **Solution 3** to test if prompt engineering helps
- **Solution 4** if you need production-quality grounding
